### Website (LIVE)
- Built a self-contained landing page at `docs/index.html`: unified-search hero
  mirroring the app, sources grid, the real GTK screenshot (embedded), features,
  per-OS downloads. Theme-aware, no external assets. Rendered it headlessly with
  Chromium and **fixed two real bugs** (content hidden without JS; download cards
  blown out by a long brew command).
- Deployed via **Netlify** (Option A — user connected the GitHub repo in the
  browser; `netlify.toml` sets publish=`docs`). **Live at https://pkgfind.netlify.app**,
  auto-redeploys on every push. Chose Netlify for a free `*.netlify.app` URL; a
  bought custom domain (e.g. pkgfind.app) is a possible later add.
- **Fixed a stale-download bug** the user caught: the site's download buttons
  were pinned to v0.5.2. Repointed them at `/releases/latest/download/...` so
  they always serve the newest release (now v0.6.0) and never go stale again.

### Updates feature → released as v0.6.0
- Added `outdated()` / `upgrade_cmd()` / `upgrade_all_cmd()` to **every** backend
  in `backends.py` (Flatpak, rpm-ostree image, DNF, APT, pacman, zypper, apk,
  snap, Homebrew, winget, Scoop, Chocolatey); new `Result.newest` field.
- **GTK app** (`app.py`): an Updates toggle in the header lists outdated apps as
  `current → newest`, with per-row Update and an Update-all button;
  `CommandDialog` now runs a sequence of commands.
- **Windows/Tkinter** (`winapp.py`): matching Updates + Update-all view.
- **CLI** (`pkgfind.py`): `--updates`, `--upgrade <id>`, `--upgrade-all`.
- Verified live via CLI and backends (caught `Homebrew node 26.5.1 → 26.6.0`)
  and drove the Tkinter view end-to-end. **GTK UI not launch-tested** — the
  sandbox kills processes that open the display (the `144` exits); it imports
  cleanly and mirrors the proven search flow.
- Released **v0.6.0**: tag `pkgfind-v0.6.0` → CI built `pkgfind-setup.exe` +
  `pkgfind.flatpak` and published the release; bumped `installer/pkgfind.iss`
  and the Homebrew `Formula/pkgfind.rb` (url/version/sha).
