# 2026-08-29 — area-select preview was blurry

## The report

> "in the openshot app: its blury when trying to take an area ss"

Clarified mid-session to `screen_capture`. (No app named "openshot" exists on
this box — nothing in `~/rolo`, pacman or flatpak.)

## What was actually wrong

Not the screenshots. The saved PNGs were always pixel-exact — inspected several
from `~/Pictures/Screenshots` and they are sharp at native size, and there is no
DPI scaling on this machine (2560x1440, no `Xft.dpi`, no `QT_SCALE_FACTOR`).

What was blurred is the **view you aim through**. `~/.config/picom.conf` had been
edited earlier the same day (12:28) to turn on `blur-background = true`
(`dual_kawase`, strength 3). The area-select overlay is a full-screen translucent
ARGB window with a transparent box punched in it, so picom blurred the whole
desktop behind it — the inside of the selection box included. Nothing legible
left to frame.

## How it was confirmed

A throwaway script (`blurtest.py`, in the job tmp dir, not kept) put up a
translucent Qt window with the same flags as `AreaSelectOverlay` and measured the
mean absolute horizontal gradient of a fixed 460x250 region as a sharpness proxy:

| state | sharpness |
|---|---|
| no overlay | 3.979 |
| overlay up (before fix) | **0.330** |
| 80 ms after close | 3.979 |
| overlay up (after fix) | **3.979** |

A 12x loss of detail while the overlay is up, and full recovery 80 ms after it
closes — which is exactly why the files on disk were fine and only the live
preview looked wrong.

## The fix — two halves

Matching on the window **title** rather than `class_g` was deliberate: a PySide6
app's WM_CLASS derives from `argv[0]`/application name and would collide with
other Python GUI apps, whereas the title is set explicitly and is ours alone.

1. **`screen_capture/area_select.py`** (in this repo) — the overlay now calls
   `setWindowTitle("screen-capture-area-overlay")` in `__init__`, giving the
   compositor a stable handle to match on. Commented in place.

2. **`~/.config/picom.conf`** (NOT in this repo — desktop config is never
   committed here) — a new final rule matching that title:

   ```
   { match = "name = 'screen-capture-area-overlay'";
     blur-background = false; opacity = 1.0; shadow = false; fade = false;
     corner-radius = 0;
     animations = ({ triggers = [ "open", "close", "show", "hide", "geometry" ]; }) }
   ```

   `fade` and the animation are switched off for a second reason beyond polish:
   `mousePressEvent` closes the overlay and grabs the screen 80 ms later, so a
   frame still fading or scaling out could be baked into the screenshot.

   Rule order matters — last match wins per option — so it sits at the end of the
   `rules` block, after the `fullscreen` rule.

## Verification

- picom reloaded in place with `pkill -USR1 -x picom` (no restart needed, no errors).
- App restarted; the overlay was then driven for real via its configured hotkey
  (`Key.alt_r`) with `xdotool` and photographed: desktop behind it fully sharp,
  the app's own 40%-black dim still applied so the box stands out.
- `area_select.py` compiles clean.
